# Motrix 2.0.0-beta.48

English | [简体中文](https://github.com/agalwood/Motrix/blob/v2.0.0-beta.48/docs/release-notes/2.0.0-beta.48.zh-CN.md)

Motrix 2.0.0-beta.48 adds declarative plugin operations, task re-download,
manual renderer recovery, compact desktop layouts, persistent speed-limit
units, and dedicated plugin proxy support. It also improves download
diagnostics, login-launch behavior, settings layout, and startup feedback.

## Highlights

- Plugins can declare bounded, localized operation forms that run through the
  existing QuickJS sandbox on desktop and Server. Host-owned jobs provide
  progress, cancellation, reconnect and resume, resource limits, and
  invocation-scoped file grants. Media merge now uses this generic interface;
  compatible operation plugins require Motrix `2.0.0-beta.48` or later
  ([#2350](https://github.com/agalwood/Motrix/pull/2350)).
- Completed regular downloads have a Re-download action in the inspector and
  context menu. It reuses saved task options, asks before using an existing
  output path, and lets Alt-click open the options for editing. Plugin startup
  and optional-hook failures are isolated so they cannot block normal download
  finalization ([#2363](https://github.com/agalwood/Motrix/pull/2363)).
- Motrix detects a failed or unresponsive renderer while downloads continue in
  the main process. Users can manually recover the affected window from the
  recovery surface, native menu, or tray without restarting the engine. This
  release observes renderer health but does not enable automatic recovery
  ([#2349](https://github.com/agalwood/Motrix/pull/2349)).
- Configuration-only `app.mainWindowMinWidth` and
  `app.mainWindowMinHeight` settings allow compact desktop layouts while
  retaining the existing 914 × 672 defaults. Downloads, Settings, the sidebar,
  and the independent recovery screen adapt to narrow windows; operating-system
  minimums can still apply ([#2356](https://github.com/agalwood/Motrix/pull/2356),
  [#2359](https://github.com/agalwood/Motrix/pull/2359)).
- Upload and download limits can be entered independently in KB/s or MB/s, or
  KiB/s and MiB/s with binary units. Switching units preserves the exact byte
  limit, and each field remembers its unit after saving and restarting
  ([#2362](https://github.com/agalwood/Motrix/pull/2362)).
- Plugin catalogs, packages, builtin updates, and security-policy requests now
  use a dedicated Plugin installation and updates proxy scope on desktop and
  Server. Last-good catalog data remains available during network failures,
  with sanitized diagnostics and retry controls
  ([#2360](https://github.com/agalwood/Motrix/pull/2360)).
- Production logs retain bounded, redacted aria2 warning and error details,
  including HTTP status and aria2 error codes that could previously be hidden
  behind a generic `No URI available.` message. User-visible errors and retry
  behavior are unchanged ([#2361](https://github.com/agalwood/Motrix/pull/2361)).
- Repeated Windows login launches preserve a running app's current visibility
  when Show window at login is disabled, while explicit launches still restore
  and focus the window ([#2348](https://github.com/agalwood/Motrix/pull/2348)).
- The Mo startup logo has a reduced-motion-aware shimmer while the main
  renderer loads ([#2364](https://github.com/agalwood/Motrix/pull/2364)).

## Before testing

This is prerelease software. Back up existing Motrix application data and
downloads before installing it. When practical, test v2 using a separate OS
account, machine, or Docker data directory.

Renderer recovery is manual in this beta. Automatic crash or hang recovery is
disabled pending broader cross-platform soak testing. Windows and Linux sleep,
GPU-fault, and long-running recovery scenarios have not completed the same
acceptance coverage as macOS.

Declarative operations depend on separately distributed compatible plugins.
File access remains scoped to the plugin invocation, and Web operation access
is additionally controlled by Server operator policy. Review every requested
file and output location before starting an operation.

The plugin proxy transport safely refuses unsupported IPv6-literal SOCKS target
URLs rather than falling back to a direct connection. Plugin catalog and package
hosts normally use domain names. Windows proxy behavior has not been manually
reverified for this beta.

Copied diagnostics redact signed URL queries, credentials, sensitive headers,
and raw request targets, but review logs before sharing because arbitrary plugin
text or URL paths may still contain sensitive data.

After the protected Snap workflow completes, install the strictly confined
build with `sudo snap install motrix --edge`. Installations tracking
`latest/edge` should upgrade to the same beta.48 revision set.

## Distribution notes

- Flatpak bundles use application ID `app.motrix.native` and the `beta` branch.
  Download each new bundle and install it with `flatpak install --user
  --or-update`; these single-file bundles do not configure a Motrix update
  remote. Update the Native Host companion separately for browser integration.
  See the
  [Flatpak guide](https://github.com/agalwood/Motrix/blob/v2.0.0-beta.48/docs/flatpak.md).
- AppImage desktop integration remains opt-in. Browser cold launch requires
  the separately enabled Native Messaging host and a registered AppImage path;
  reconnecting with a saved pairing also requires a compatible Extension.
- Motrix application packages for Windows `arm64` and all 32-bit targets are
  unavailable. Windows app packages are unsigned and may trigger SmartScreen;
  download them only from the official published GitHub prerelease.
- Beta container tags are immutable and do not update `latest`, `stable`, or
  other stable-channel aliases.
- Snap uses strict confinement. Its approved `personal-files` interface is
  limited to Native Messaging host registration for supported browsers. Beta
  publication updates `latest/edge` only.
