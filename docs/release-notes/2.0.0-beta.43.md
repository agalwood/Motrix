# Motrix 2.0.0-beta.43

English | [简体中文](https://github.com/agalwood/Motrix/blob/v2.0.0-beta.43/docs/release-notes/2.0.0-beta.43.zh-CN.md)

Motrix 2.0.0-beta.43 packages the Safari desktop bootstrap in signed macOS
builds and improves registration when upgrading or switching installed copies.
The Safari extension remains independently distributed.

## Highlights

- macOS arm64 and x64 packages now include the Safari bootstrap service,
  registrar, and LaunchAgent. The helpers receive their required signatures and
  App Group entitlement before the app passes the existing notarization and
  package-verification gates ([#2271](https://github.com/agalwood/Motrix/pull/2271)).
- Opening the installed Motrix app verifies that the registered service belongs
  to that app. Stale or mismatched registrations are rebound with bounded
  retries, while a matching service stays running. If macOS requires background
  item approval, Motrix preserves that state instead of overriding your choice
  ([#2271](https://github.com/agalwood/Motrix/pull/2271)).
- Safari bootstrap stops after one nonce request when a running bridge refuses
  it, avoiding unnecessary launch attempts and retries. A stopped bridge can
  still trigger the cold-launch path. The extension-facing protocol remains
  compatible, with regression coverage using the production Swift/Rust adapter
  ([#2271](https://github.com/agalwood/Motrix/pull/2271)).

## Before testing

This is prerelease software. Back up existing Motrix application data and
downloads before installing it. Migration from Motrix v1 data has not yet been
validated, so do not use your only copy of v1 data with this beta.

When practical, test v2 in parallel using a separate OS account, machine, or
Docker data directory.

For Safari integration, install or update the signed macOS app, then open the
intended Motrix.app once to register its bootstrap service. Approve the
background item if macOS requests it. Downloading the app alone does not change
registration; opening another signed copy can change the registered owner.
Use a compatible, separately distributed Safari extension and test cold launch
and paired reconnection after the upgrade. Do not delete your database or
pairing credentials to resolve an old launch target.

Automated package and Swift/Rust integration checks do not replace clean-Mac
upgrade and cold-launch acceptance testing.

After the protected Snap workflow completes, testers can install the strictly
confined build with `sudo snap install motrix --edge`. Existing installations
tracking `latest/edge` should upgrade to the same beta.43 revision set.

## Distribution notes

- Flatpak bundles use application ID `app.motrix.native` and the `beta` branch.
  Download each new bundle and install it with `flatpak install --user
  --or-update`; no Motrix update remote is configured by these single-file
  bundles. Update the Native Host companion separately when using browser
  integration. See the
  [Flatpak guide](https://github.com/agalwood/Motrix/blob/v2.0.0-beta.43/docs/flatpak.md).
- AppImage desktop integration remains opt-in. Browser cold launch requires
  the separately enabled Native Messaging host and a registered AppImage path;
  reconnecting with a saved pairing also requires a compatible Extension.
- Windows `arm64` and all 32-bit packages are unavailable. Windows packages are
  unsigned and may trigger Windows SmartScreen warnings; download them only
  from the official published GitHub prerelease.
- Beta container tags are immutable and do not update `latest`, `stable`, or
  other stable-channel aliases.
- Snap packages use strict confinement. The approved `personal-files`
  interface is limited to Native Messaging host registration for supported
  browsers. Beta publication updates `latest/edge` only.
