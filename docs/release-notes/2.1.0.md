# Motrix 2.1.0

English | [简体中文](https://github.com/agalwood/Motrix/blob/v2.1.0/docs/release-notes/2.1.0.zh-CN.md)

Motrix 2.1.0 adds tools for managing existing BitTorrent files, an opt-in
Windows portable profile, editable HTTP retry parameters, and native Linux
window controls. It also improves large-torrent handling, migration, and updates.

## Changes since 2.0.1

- Move, locate, and check existing BitTorrent files from the desktop or Web UI.
  Verified files can be adopted without losing the task ID or history, with an
  option to resume seeding. Local v1 torrent pieces are checked before adoption;
  missing or damaged data is reported without starting a repair download.
  Moving an active partial download remains outside this workflow.
- Enable Windows portable mode by creating a `data` folder beside `Motrix.exe`
  in an extracted ZIP. The profile, plugins, working files, and temporary data
  stay beside the application. Application-owned paths are adjusted when the
  folder moves; external destinations require attention before affected work
  resumes. Portable copies use manual ZIP updates and do not install system
  integrations. See the [portable-mode guide](https://github.com/agalwood/Motrix/blob/v2.1.0/docs/portable-mode.md).
- Retry eligible failed HTTP tasks with edited URLs, request headers,
  authentication, proxy settings, and download options. The dialog creates a
  separate download and preserves the failed task, partial file, and checkpoint.
  Existing automatic retries remain available; Alt+Retry opens the parameter
  form for eligible failures.
- Use native Linux window controls that follow Electron-supported desktop
  layouts and themes. Toolbars and popup menus avoid the native control area,
  including left/right layouts and fullscreen transitions.
- Support large, many-file torrent requests within an explicit 64 MiB desktop
  engine RPC budget, and report protocol failures instead of misleading timeouts.
  Server retains its configured request budget. Compact list polling, cached file
  metadata, visible-only detail refreshes, and bounded piece-map rendering reduce
  repeated work for large tasks.
- Migrate legacy tasks containing old proxy or unsupported options with clear
  notices. Verification and continuation use the current download proxy policy;
  HTTP content verification and existing-file protections remain in place.
- Serialize macOS update installation requests and offer manual replacement
  when application and temporary locations are on different volumes or cannot
  be checked safely. Eligible same-volume locations are not restricted to
  `/Applications`.
- Restrict Liquid Glass to the macOS desktop app, and defer empty-state WebGL
  initialization so text and navigation appear first. Fix plugin-operation IDs
  when the Web UI is opened over LAN HTTP, and improve Windows tray icons.
- Update Electron to **45.1.0**, along with compatible UI, form, routing,
  internationalization, and static-server dependencies. `vscode-jsonrpc` remains
  at **9.0.3**. The bundled engine remains **aria2 1.37.0-motrix.21**.

## Downloads and updates

Desktop packages support macOS 13 or later, Windows 10 or later, and Linux,
with native x64 and ARM64 builds. No 32-bit desktop packages are provided.
macOS DMG and ZIP packages are signed and notarized. Windows NSIS installers
and ZIP archives are unsigned and may trigger SmartScreen; download them from
the official GitHub Release.

Stable publication updates both `latest*.yml` and `beta*.yml` feeds to 2.1.0.
Flatpak bundles and their Native Host companions remain separate downloads;
see the [Flatpak guide](https://github.com/agalwood/Motrix/blob/v2.1.0/docs/flatpak.md).
Snap builds first reach `latest/edge`; the same verified amd64 and arm64 revisions
are then promoted through candidate to stable.

Server images use the immutable tags `docker.io/motrixapp/motrix-server:2.1.0`
and `ghcr.io/agalwood/motrix-server:2.1.0`. After public multi-platform runtime
verification, the `2.1`, `2`, `stable`, and `latest` aliases advance to this version.
See the [Docker Server guide](https://github.com/agalwood/Motrix/blob/v2.1.0/docs/docker-server.md).

Back up your profile and download files before upgrading. Users migrating
from Motrix v1 should follow the
[migration guide](https://github.com/agalwood/Motrix/blob/v2.1.0/docs/legacy-migration.md)
and retain their original profile and engine database backups.

## Known limitations

- The parameter-based HTTP retry starts a new download. It does not implement
  authenticated continuation of a retained partial file or establish that the
  Windows DNS/resume failures in [#2426](https://github.com/agalwood/Motrix/issues/2426)
  are resolved.
- Windows portable relocation across real drives still needs broader native
  validation. Follow the portable-mode guide and retain the original folder
  until the moved profile and downloads have been checked.
- Linux window controls depend on Electron-supported desktop behavior.
  Final native GNOME retesting and coverage of KDE Plasma, X11, and WhiteSur
  remain incomplete; no application-level traffic-light style selector is added.
- New BT storage-dialog text is translated into English, Simplified Chinese,
  and Traditional Chinese. Other languages currently use English for these keys.
