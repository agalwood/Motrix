# Motrix 2.0.0-beta.47

English | [简体中文](https://github.com/agalwood/Motrix/blob/v2.0.0-beta.47/docs/release-notes/2.0.0-beta.47.zh-CN.md)

Motrix 2.0.0-beta.47 adds a desktop Migration Assistant for v1 tasks, signed
official optional plugin installation, and host support for manual audio/video
merging. It includes all updates since beta.46, with improved permission review,
download finalization and storage recovery, window restoration, diagnostic logs,
and the bundled aria2 `1.37.0-motrix.17` engine.

## Highlights

- The desktop Migration Assistant discovers a v1 profile or accepts a chosen
  folder, previews tasks, and imports selected records in a paused state while
  preserving the original files. It supports metadata backups, duplicate
  detection, interrupted runs, retry, and report export. Compatible BitTorrent
  tasks can be verified and activated separately with explicit directory
  authorization ([#2331](https://github.com/agalwood/Motrix/pull/2331)).
- The bundled aria2 `1.37.0-motrix.17` provides native legacy checkpoint import
  and durable paused BitTorrent recovery. It preserves a complete pre-upgrade
  SQLite snapshot before upgrading the engine database to schema 5
  ([#2342](https://github.com/agalwood/Motrix/pull/2342)).
- Signed official optional plugins can be installed from the marketplace on
  desktop and Server. Motrix verifies their signed archives, retains normal
  permission consent and uninstall behavior, and explains incompatible host
  versions before installation
  ([#2312](https://github.com/agalwood/Motrix/pull/2312)).
- Manual media merging can combine separate local video and audio files into
  MP4 or MKV through a compatible, enabled `motrix.media-merge` plugin and
  configured FFmpeg. The form appears in the plugin's Operations tab and in the
  action menu for two completed single-file downloads. Source files are
  preserved, and existing output files are not replaced. The companion plugin
  is installed separately; this host release does not bundle it or automatically
  merge downloads ([#2308](https://github.com/agalwood/Motrix/pull/2308)).
- Plugin package preparation stays in the install button until permissions are
  ready to review. Required and optional permissions are grouped, optional
  access starts disabled, and consent remains stable during confirmation,
  cancellation, and dialog exit
  ([#2333](https://github.com/agalwood/Motrix/pull/2333),
  [#2335](https://github.com/agalwood/Motrix/pull/2335)).
- Download finalization handles macOS exFAT suffix removal, actual cross-mount
  move failures, and unavailable storage recovery more reliably. Pending
  journals survive offline storage while other tasks can recover; changed or
  uncertain files retain conflict protection
  ([#2330](https://github.com/agalwood/Motrix/pull/2330),
  [#2339](https://github.com/agalwood/Motrix/pull/2339)).
- Startup activation and minimized-window restoration are preserved. The
  Downloads scrollbar stays below its column header, signed macOS releases
  restore the permission needed for shutdown after completion, and production
  bundles and deferred desktop loading are optimized
  ([#2325](https://github.com/agalwood/Motrix/pull/2325),
  [#2323](https://github.com/agalwood/Motrix/pull/2323),
  [#2337](https://github.com/agalwood/Motrix/pull/2337),
  [#2316](https://github.com/agalwood/Motrix/pull/2316)).
- Plugin diagnostics preserve ordinary URL query values while masking common
  credential names. Correlated task-creation entries make URL rewrites easier
  to inspect. Verbose mode expires after one hour, and copying logs applies
  stricter redaction ([#2340](https://github.com/agalwood/Motrix/pull/2340)).
- Signed plugin security policy enforcement is implemented, but production
  trust and the signed feed remain unconfigured in this release. Synchronization
  is dormant; this beta does not provide live security advisory blocking
  ([#2326](https://github.com/agalwood/Motrix/pull/2326)).
- Electron, pnpm, packaging tools, dependency locks, GitHub Actions, and
  regression coverage are refreshed
  ([#2336](https://github.com/agalwood/Motrix/pull/2336),
  [#2341](https://github.com/agalwood/Motrix/pull/2341),
  [#2344](https://github.com/agalwood/Motrix/pull/2344)).

## Before testing

This is prerelease software. Back up existing Motrix application data and
downloads before installing it. When practical, test v2 using a separate OS
account, machine, or Docker data directory.

Migration imports records without automatically resuming them. HTTP tasks use
the explicit new-download flow in a separate destination. In-place BitTorrent
continuation requires compatible original metadata, file selection, engine
support, and explicit authorization. The assistant is desktop-only; Windows
explicitly refuses unsupported legacy progress import. Keep the v1 profile and
original files backed up. Older engines refuse schema 5, so an engine downgrade
requires the compatible pre-upgrade database snapshot.

Manual media merging requires a separately published signed companion plugin
compatible with beta.47 and configured FFmpeg. Availability depends on its
signed release and registry listing. To install FFmpeg, open Settings →
Integration → Media tools. Active plugins need a Motrix restart to detect a new
managed installation. See the [FFmpeg manual](https://motrix.app/manual/ffmpeg/).

The macOS exFAT publication fallback assumes application ownership of the
reserved target name during publication; it cannot guarantee atomic no-overwrite
against an external process replacing that reservation. Unsupported or
ambiguous filesystem operations remain safe refusals or conflicts.

Copied diagnostics mask all URL query values and omit structured headers and
bodies. Review logs before sharing: arbitrary plugin text or URL paths may still
contain sensitive data, and existing verbose log files remain after expiry.

After the protected Snap workflow completes, install the strictly confined
build with `sudo snap install motrix --edge`. Installations tracking
`latest/edge` should upgrade to the same beta.47 revision set.

## Distribution notes

- Flatpak bundles use application ID `app.motrix.native` and the `beta` branch.
  Download each new bundle and install it with `flatpak install --user
  --or-update`; these single-file bundles do not configure a Motrix update
  remote. Update the Native Host companion separately for browser integration.
  See the [Flatpak guide](https://github.com/agalwood/Motrix/blob/v2.0.0-beta.47/docs/flatpak.md).
- AppImage desktop integration remains opt-in. Browser cold launch requires
  the separately enabled Native Messaging host and a registered AppImage path;
  reconnecting with a saved pairing also requires a compatible Extension.
- Motrix application packages for Windows `arm64` and all 32-bit targets are
  unavailable. Windows app packages are unsigned and may trigger SmartScreen;
  download them only from the official published GitHub prerelease.
- Beta container tags are immutable and do not update `latest`, `stable`, or
  other stable-channel aliases.
- Snap uses strict confinement. Its approved `personal-files` interface is
  limited to Native Messaging host registration for supported browsers. Beta
  publication updates `latest/edge` only.
