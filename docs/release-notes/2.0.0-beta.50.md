# Motrix 2.0.0-beta.50

English | [简体中文](https://github.com/agalwood/Motrix/blob/v2.0.0-beta.50/docs/release-notes/2.0.0-beta.50.zh-CN.md)

Motrix 2.0.0-beta.50 adds live task activity charts and history navigation,
improves torrent and download interactions, and makes configuration recovery,
plugin diagnostics, and session persistence more reliable.

## Highlights

- Task activity now shows separate download and upload curves with a history
  overview, range selection, zoom, and keyboard navigation. Active downloads
  and seeding tasks follow the latest 60 seconds; completed tasks open their
  full history. Browsing history preserves your chosen range as new samples
  arrive, and completed history stays fixed across restarts
  ([#2387](https://github.com/agalwood/Motrix/pull/2387)).
- Drop `.torrent` files onto the app window to open Add Task with the files
  ready. Drops respect sign-in and session changes. Download-list checkboxes
  return for touch-friendly selection, and failed file-opening actions provide
  clearer guidance
  ([#2374](https://github.com/agalwood/Motrix/pull/2374),
  [#2377](https://github.com/agalwood/Motrix/pull/2377),
  [#2381](https://github.com/agalwood/Motrix/pull/2381),
  [#2370](https://github.com/agalwood/Motrix/pull/2370)).
- Settings → Advanced shows the active configuration path. Desktop can reveal
  the configuration file in its folder; Server Web can copy its path. Invalid
  configuration files are backed up before defaults are restored, and a failed
  backup prevents replacement. Long paths use consistent middle truncation
  while preserving full values for copying and file operations
  ([#2382](https://github.com/agalwood/Motrix/pull/2382),
  [#2384](https://github.com/agalwood/Motrix/pull/2384)).
- Plugin failures remain available in persistent logs after restarting Motrix.
  Disabled plugins stop contributing task-menu actions, event subscriptions
  clean up reliably, and switching operation formats no longer flickers
  ([#2380](https://github.com/agalwood/Motrix/pull/2380),
  [#2376](https://github.com/agalwood/Motrix/pull/2376)).
- Media downloads, Server save-directory preparation, and legacy re-downloads
  accept existing volume roots without redundant directory creation. Empty
  engine IDs are stored as database `NULL` values, with existing empty entries
  repaired on upgrade, preventing uniqueness failures from interrupting task
  persistence
  ([#2383](https://github.com/agalwood/Motrix/pull/2383),
  [#2386](https://github.com/agalwood/Motrix/pull/2386)).
- Choosing **Not now** in migration hides its sidebar shortcut across restarts;
  migration remains available in **Settings → Advanced**. Settings cards and
  the startup overlay also receive visual feedback refinements
  ([#2378](https://github.com/agalwood/Motrix/pull/2378)).
- Language changes preserve engine restart reminders and pending restart state.
  Late activation events during quit cleanup cannot reopen a window or briefly
  show the renderer recovery screen
  ([#2385](https://github.com/agalwood/Motrix/pull/2385),
  [#2391](https://github.com/agalwood/Motrix/pull/2391)).

## Before testing

This is prerelease software. Back up existing Motrix data and downloads before
installing it. When practical, test v2 with a separate OS account, machine or
Docker data directory.

The Migration Assistant does not import or resume downloads automatically.
Manual migration preserves original files and imports selected tasks as paused
records; legacy progress import remains unavailable on Windows.

Persistent plugin logs cannot reconstruct errors that older versions never
wrote to disk. Native Windows end-to-end verification of the expanded
volume-root paths remains pending. Renderer recovery remains manual, with
broader Windows/Linux sleep, GPU-fault and long-running recovery acceptance
still pending.

After the protected Snap workflow completes, install the strictly confined build
with `sudo snap install motrix --edge`. Installations tracking `latest/edge`
should upgrade to the beta.50 revision set.

## Distribution notes

- Flatpak bundles use application ID `app.motrix.native` and the `beta` branch.
  Install each new bundle with `flatpak install --user --or-update`; these files
  do not configure a Motrix update remote. Update the Native Host companion
  separately. See the [Flatpak guide](https://github.com/agalwood/Motrix/blob/v2.0.0-beta.50/docs/flatpak.md).
- AppImage desktop integration remains opt-in. Browser cold launch requires the
  separately enabled Native Messaging host and a registered AppImage path;
  reconnecting to a saved pairing also requires a compatible Extension.
- Windows `arm64` and all 32-bit app packages are unavailable. Windows packages
  are unsigned and may trigger SmartScreen; use the official published GitHub
  prerelease.
- Beta container tags are immutable and do not change `latest`, `stable`, or
  other stable-channel aliases. Snap publication updates `latest/edge` only.
