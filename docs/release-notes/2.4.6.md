# Motrix 2.4.6

English | [简体中文](https://github.com/agalwood/Motrix/blob/main/docs/release-notes/2.4.6.zh-CN.md)

## Changes since 2.4.5

- **Bundled aria2 1.37.0-motrix.26 (#2551, #2556)**: Allow dynamic CDN/mirror redirect targets when resuming or splitting HTTP downloads with matching source identity, output path, total length, and validator (`ETag` / `Last-Modified`) without HTTPS downgrade, restoring full multi-connection download speeds.
- **Reliable HTTP content length & resume (#2540, #2554)**: Disable `http-accept-gzip` globally and align metadata probes to `identity` encoding so large files preserve `Content-Length`, progress percentages, multi-segment splitting, and resumability.
- **macOS SMB share finalization (#2549, #2555)**: Support macOS `smbfs` mounts by falling back from `F_FULLFSYNC` to `fsync` (`remote_acknowledged`) and tolerating synthetic `st_ino` changes across `renameat` on reserved outputs.
- **Direct magnet save directory (#2552, #2553)**: Keep direct magnet downloads in the selected `saveDir` instead of an extra `infoHash` subfolder and reconcile `followedBy` metadata transitions cleanly.
- **BitTorrent listening port migration (#2462, #2558)**: Migrate legacy default BT/DHT listening ports off `6881` to `21301` / `26701` once while preserving custom ports, and surface explicit `BtPortBindFailed` diagnostics when port binding fails.
- **Resilient aria2 startup probing (#2517, #2559)**: Retry transient OS lock/permission/timeout errors (`EBUSY`, `EACCES`, `ETIMEDOUT`, etc.) with bounded backoff during `aria2c --version` probing so brief antivirus scans on Windows do not falsely report a missing engine binary.
- **Signed redirect resume verification (#2426, #2488, #2560)**: Ignore transient signed-URL and expiring-token query parameters (such as GitHub Releases / Azure SAS, AWS S3 / R2, GCS, Aliyun OSS, and Tencent COS tokens) when verifying cross-origin redirect targets for resume, while still rejecting origin, path, or content-parameter changes.
- **Bounded log & temp disk usage (#2532, #2561)**: Rotate `motrix.log` automatically at runtime (capped at 5 MiB with one `.1` backup) and clean stale `motrix-media-*` temporary directories on startup.
- **Configurable opening downloads view (#2543)**: Allow remembering the last opened downloads view or choosing a fixed startup view.

## Upgrade compatibility

**Back up your profile and download files before upgrading.** The bundled engine
uses SQLite **schema 6**. When upgrading an older engine database, retain its
complete pre-upgrade backup; older engines cannot open schema 6. Stop all engines
before restoring a verified backup to a separate path for a downgrade. Do not
reset or delete the upgraded database as a substitute for recovery.

Users migrating from Motrix v1 should follow the
[migration guide](https://github.com/agalwood/Motrix/blob/v2.4.6/docs/legacy-migration.md)
and retain the original profile and engine database backups.

## Downloads and updates

Desktop packages support macOS 13 or later, Windows 10 or later, and Linux, with
native x64 and ARM64 builds. No 32-bit desktop packages are provided. Official
macOS packages require signing and notarization. Windows NSIS installers and ZIP
archives are unsigned and may trigger SmartScreen; use official Release downloads.

Stable publication updates both `latest*.yml` and `beta*.yml` feeds to 2.4.6.
Flatpak bundles and Native Host companions remain separate downloads. Snap
availability requires verified Store publication to edge and promotion of the
same amd64/arm64 revisions through candidate to stable.

Server images use `docker.io/motrixapp/motrix-server:2.4.6` and
`ghcr.io/agalwood/motrix-server:2.4.6`. After public multi-platform runtime
verification, `2.4`, `2`, `stable`, and `latest` advance to the same verified digest.
See the [Docker Server guide](https://github.com/agalwood/Motrix/blob/v2.4.6/docs/docker-server.md).
