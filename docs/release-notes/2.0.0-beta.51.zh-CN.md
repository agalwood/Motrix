# Motrix 2.0.0-beta.51

[English](https://github.com/agalwood/Motrix/blob/v2.0.0-beta.51/docs/release-notes/2.0.0-beta.51.md) | 简体中文

Motrix 2.0.0-beta.51 捆绑 aria2 1.37.0-motrix.18，支持 Windows 旧版 BitTorrent 进度恢复，修复 Windows 任务路径和关闭动画，并为 Server 管理员增加终端扩展配对。

## 主要改进

- Windows 可通过原生 checkpoint 和 torrent 元数据恢复能力激活已导入的旧版 BT 任务。捆绑的 aria2 1.37.0-motrix.18 提供所需能力，应用保留路径身份、原始文件选择、持久化授权，以及响应丢失或重启后的恢复。原生 Windows 消费端测试已在 Windows 2022 x64、Windows 2025 x64/ia32 上通过；Motrix 桌面安装包仍仅提供 x64（[#2397](https://github.com/agalwood/Motrix/pull/2397)、[#2399](https://github.com/agalwood/Motrix/pull/2399)）。
- Windows 任务路径在显示和复制时统一使用原生分隔符。打开文件或在资源管理器中定位时，正确处理重复分隔符、磁盘根目录和 UNC 路径，已有任务同样生效（[#2395](https://github.com/agalwood/Motrix/pull/2395)）。
- 菜单、对话框和任务表单在关闭动画期间保持内容与尺寸稳定，同时立即停用操作。活动图表在最近与完整历史范围之间切换后，下一个样本不会重播旧范围的缩放动画。快速重新打开插件输入对话框时，会拒绝先前会话迟到的文件准备结果（[#2396](https://github.com/agalwood/Motrix/pull/2396)）。
- 完整配置 WS/WSS 端点后，Server 扩展配对不再强制要求 `MOTRIX_PUBLIC_URL`。经过鉴权的管理员可在本机交互式终端运行 `motrix-admin extension pair`，选择待处理请求并查看短期配对码；用户仍须在扩展中输入该码完成授权。配对码拒绝通过重定向或 JSON 输出，Web 分发仍要求 HTTPS 或明确授权使用 HTTP。管理员 CLI 翻译也不再将完整应用语言目录重复打包进 Server（[#2400](https://github.com/agalwood/Motrix/pull/2400)）。

## 测试前须知

请备份 v1 配置和下载文件，关闭旧版应用，并核对所选任务。迁移仅导入暂停记录，不会开始传输或修改原文件。BT 激活需要原始 torrent 元数据、原始文件选择和目录，以及明确授权。传输前会校验已有分片；重启后需明确恢复暂停的任务。

Windows 进度恢复要求本地固定 NTFS 卷，以及符合要求的文件所有权和权限。网络共享、FAT/exFAT、junction、符号链接、云盘 reparse point、硬链接文件、备用数据流和别名路径会被拒绝。HTTP 记录仍下载到独立目录，迁移助手不会在原位置复用历史 HTTP 数据。具体要求与恢复行为见[迁移指南](https://github.com/agalwood/Motrix/blob/v2.0.0-beta.51/docs/legacy-migration.zh-CN.md)。升级旧数据库时请保留引擎的 pre-schema5 备份。

真实 Windows SMB 共享上的资源管理器行为和原生 fnOS 验收仍未完成。完整 Chromium 扩展下载提交 E2E 在可用的生产扩展构建上仍遇到基线已有的 `download.rejected` 失败，本版本不宣称该套件通过；Server 协议及真实 HTTP 配对、重连测试已通过。

受保护的 Snap 工作流完成后，可用 `sudo snap install motrix --edge` 安装严格沙箱版本。跟随 `latest/edge` 的安装应更新到 beta.51 对应的修订集合。

## 发行说明

- Flatpak 使用应用 ID `app.motrix.native` 和 `beta` 分支。新包通过 `flatpak install --user --or-update` 安装；单个包文件不会配置 Motrix 更新源。Native Host 配套包需要单独更新，详见 [Flatpak 指南](https://github.com/agalwood/Motrix/blob/v2.0.0-beta.51/docs/flatpak.zh-CN.md)。
- AppImage 桌面集成仍由用户选择启用。浏览器冷启动需要单独启用 Native Messaging host 并注册 AppImage 路径；恢复已有配对还需要兼容的 Extension。
- 尚无 Windows `arm64` 或任何 32 位应用包。Windows 包未签名，可能触发 SmartScreen，请从官方公开的 GitHub 预发布页面下载。
- beta 容器标签不可变，不更新 `latest`、`stable` 或其他稳定通道别名。Snap 发布只更新 `latest/edge`。
