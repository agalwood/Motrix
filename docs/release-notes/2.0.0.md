# Motrix 2.0.0

English | [简体中文](https://github.com/agalwood/Motrix/blob/v2.0.0/docs/release-notes/2.0.0.zh-CN.md)

Motrix 2.0.0 is the first stable release of Motrix v2, rebuilt with Electron,
React, and TypeScript. It brings the desktop download manager and the headless
Server with a Web UI onto a shared download core.

## Highlights

- HTTP, FTP, BitTorrent, and magnet downloads with file selection, persistent
  sessions, tracker management, and configurable speed limits.
- A customizable dashboard, task activity charts, light and dark themes,
  system notifications, and an in-app notification center.
- Sandboxed plugins with explicit capabilities, an in-app plugin marketplace,
  and signed official plugins for filename templates and URL resolution.
- Browser integration through Motrix Extension and Native Messaging, plus the
  `@motrix/cli` command-line client and MDXP protocol for local and remote use.
- A headless Server for Docker, NAS, and home servers, with a Web UI and
  device-code pairing for remote CLI clients.
- Native x64 and ARM64 desktop packages on Windows, macOS, and Linux, bundling
  aria2 1.37.0-motrix.19. No 32-bit desktop packages are provided.

## Changes since beta.52

- New installations follow the system language by default; existing language
  preferences are preserved.
- Ordinary Windows download completion removes the temporary suffix without
  hashing the entire file. Copy and plugin-modified outputs retain content
  verification, and interrupted renames retain recovery checks.
- Updated desktop and Server dependencies, including Electron 45. Maximized
  windows restore their state after being shown, and dashboard transfer bars
  animate width changes.

## Downloads and update channels

| Distribution | Architectures | Output |
|--------------|---------------|--------|
| macOS 13 or later | `arm64`, `x64` | Signed and notarized DMG and ZIP |
| Windows 10+ | `x64`, `arm64` | Unsigned NSIS installer and ZIP |
| Linux | `x64`, `arm64` | AppImage, DEB, RPM, and pacman |
| Flatpak application | `x86_64`, `aarch64` | Versioned `.flatpak` bundle |
| Flatpak Native Host companion | `linux/x64`, `linux/arm64` | Versioned `.tar.gz` archive |
| Docker Hub / GHCR | `linux/amd64`, `linux/arm64` | Immutable `2.0.0` tag |
| Snap Store | `amd64`, `arm64` | Same verified revisions promoted through edge, candidate, and stable |

Windows packages are unsigned and may trigger SmartScreen. Download from the
official GitHub Release. Use `Motrix-Setup-2.0.0.exe` for x64 or
`Motrix-Setup-2.0.0-arm64.exe` for ARM64. An x64 installation on Windows ARM
stays on the x64 update path. Back up your profile and close Motrix before
switching architectures; do not run both builds against the same profile.

Stable publication updates both the `latest*.yml` and `beta*.yml` desktop
feeds to 2.0.0, allowing existing v2 beta installations to move to this release.
Flatpak bundles require manual updates with `flatpak install --user --or-update`;
update the Native Host companion separately. See the
[Flatpak guide](https://github.com/agalwood/Motrix/blob/v2.0.0/docs/flatpak.md).
Snap builds are initially published to `latest/edge` and promoted without
rebuilding. Once `latest/stable` promotion completes, install with
`sudo snap install motrix`.

Use `docker.io/motrixapp/motrix-server:2.0.0` or
`ghcr.io/agalwood/motrix-server:2.0.0`. The `2.0`, `2`, `stable`, and `latest`
aliases are promoted only after the immutable multi-platform images pass their
public runtime checks. See the
[Docker Server guide](https://github.com/agalwood/Motrix/blob/v2.0.0/docs/docker-server.md).

## Upgrading from Motrix v1 or a v2 beta

The stable update feed is also used by Motrix v1. Before accepting an update,
check the platform requirements above. Systems older than macOS 13, Windows 7/8/8.1, and all 32-bit Windows
installations cannot run this release and should keep their compatible version
until the operating system or hardware is upgraded.

Back up the profile and downloads before upgrading, and close the old app.
The desktop Migration Assistant imports selected v1 tasks as paused records;
importing alone does not start downloads or change the original files.
BitTorrent progress reuse requires the original metadata, original directory,
and explicit authorization. On Windows it requires a local fixed NTFS volume
and the ownership, path, and permission checks in the
[migration guide](https://github.com/agalwood/Motrix/blob/v2.0.0/docs/legacy-migration.md).
Imported HTTP records use a separate directory when activated.

Retain the engine's `*.pre-schema5-*.db` backup. An older engine cannot open
the upgraded database; use a verified backup in a separate path if a downgrade
is necessary.

## Verification limits

Real Windows SMB Explorer behavior, native fnOS acceptance, and the complete
Chromium Extension download-submission flow remain outside this release's
verified coverage. Report reproducible issues with your OS, architecture,
package type, and reproduction steps.
