# Internationalization

Every user-visible application or operator string must use i18next; do not
hardcode UI labels, messages, notifications, dialogs, or CLI output. Renderer
components use `react-i18next`; Electron main uses the initialized instance
from `src/main/lib/i18n.ts`; the server operator CLI creates an isolated
instance from shared resources. Keep `t` in React hook dependency arrays.
Route host-wide locale changes through `LocaleCoordinator`: serialize changes,
skip stale revisions, reconcile late targets, and publish `LocaleChanged` only
after the current apply succeeds. Keep plugin-registry and capability-host
locale changes transactional, including rollback on failure.

## Resource contract

- `src/shared/locales/en-US.json` is the key-shape source of truth. Add every
  logical key to every locale registered in `SUPPORTED_LOCALES`; never update
  only a subset.
- `src/shared/i18n-resources.ts` statically and exhaustively registers those
  locale files. New languages also require a catalog entry in
  `src/shared/constants/locales.ts` and a matching JSON resource.
- Every translation leaf is a string. Keep readable locale files as UTF-8;
  avoid unnecessary `\uXXXX` escapes.
- Preserve the exact `{{placeholder}}` set across every locale and every plural
  variant.
- Plural keys use i18next category suffixes. Supply every cardinal category
  returned by `Intl.PluralRules(locale)`; `_zero` is the only permitted extra
  category because i18next treats it as an exact-zero override.

## Namespaces

Keys follow the feature that owns them and use camelCase leaves; descriptions
normally pair `name` with `nameDesc`.

- Settings grid cards: `settings.cards.<card>.*`
- Settings dialogs/pages: `settings.<dialog>.*`
- BitTorrent settings and tracker defaults: `settings.bittorrent.*`
- Tracker management: `trackers.effective.*`, `trackers.blacklist.*`,
  `trackers.combobox.*`, and `trackers.sync.*`

Extend the relevant namespace rather than creating a parallel spelling or
placing tracker UI under settings merely because trackers are configurable.

## Marketplace locale independence

Application locales and registry listing locales are separate contracts.
`SupportedLocale` must not constrain `listing.defaultLocale` or keys in the
registry's open BCP 47 `listing.localizations` map. Resolve marketplace display
and search text with the vendored registry resolver; do not use
`resolveSupportedLocale` or infer sibling regions such as `zh-TW -> zh-CN`.

## Verification

Run `pnpm run check:i18n` after any locale, catalog, placeholder, plural, or
resource-registration change. It verifies file/catalog parity, logical key
coverage, plural categories, string leaves, and placeholder parity. Its tests
must use temporary fixtures and never rewrite real locale files. Tests that
render translated components load the real renderer initialization with:

```ts
import '@renderer/lib/i18n'
```
